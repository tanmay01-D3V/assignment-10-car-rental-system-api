# Car Rental & Fleet Booking System API

Production-ready Car Rental and Vehicle Fleet Management REST API built with Node.js, Express.js, and Supabase (PostgreSQL and Supabase Auth).

## Tech Stack

- Node.js
- Express.js
- Supabase (@supabase/supabase-js)
- dotenv
- cors
- nodemon

## Setup & Installation

1. Install dependencies:
```bash
npm install
```

2. Configure environment variables in `.env`:
```env
PORT=5000
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-supabase-anon-key
```

3. Execute SQL migration:
Run the queries from `schema.sql` in your Supabase SQL Editor:
```sql
CREATE TABLE vehicles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    brand TEXT NOT NULL,
    model TEXT NOT NULL,
    year INT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
    daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
    fuel_type TEXT NOT NULL,
    seating_capacity INT NOT NULL DEFAULT 5,
    status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE TABLE rentals (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL,
    vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
    customer_name TEXT NOT NULL,
    customer_email TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    total_cost NUMERIC(10, 2) NOT NULL,
    status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);
```

4. Start development server:
```bash
npm run dev
```

5. Start production server:
```bash
npm start
```

## API Specification

### Authentication

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|---|---|---|
| POST | `/api/auth/register` | No | Register new customer | 201, 400 |
| POST | `/api/auth/login` | No | Authenticate user and obtain JWT | 200, 401 |

#### Register Request Body
```json
{
  "email": "driver@travel.com",
  "password": "mypassword123",
  "name": "David"
}
```

#### Login Request Body
```json
{
  "email": "driver@travel.com",
  "password": "mypassword123"
}
```

### Vehicle Fleet Management

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|---|---|---|
| GET | `/api/vehicles` | No | Fetch all vehicles with optional filters (`?category=SUV&status=available`) | 200 |
| GET | `/api/vehicles/:id` | No | Get vehicle details with past rental records | 200, 404 |
| POST | `/api/vehicles` | Yes | Add new vehicle to fleet | 201, 400 |
| PUT | `/api/vehicles/:id` | Yes | Update vehicle rate, status, or details | 200, 404 |
| DELETE | `/api/vehicles/:id` | Yes | Delete vehicle (blocked if active/booked rentals exist) | 200, 400, 404 |

#### Add Vehicle Request Body
```json
{
  "brand": "Tesla",
  "model": "Model 3",
  "year": 2024,
  "category": "Electric",
  "daily_rate": 4500,
  "fuel_type": "EV",
  "seating_capacity": 5
}
```

#### Update Vehicle Request Body
```json
{
  "daily_rate": 4800,
  "status": "maintenance"
}
```

### Rentals & Booking Operations

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|---|---|---|
| POST | `/api/rentals` | Yes | Book vehicle with date collision check & pricing calculation | 201, 400, 404 |
| GET | `/api/rentals/my-bookings` | Yes | List all rentals for authenticated user | 200 |
| PATCH | `/api/rentals/:id/cancel` | Yes | Cancel an upcoming booking | 200, 400, 403, 404 |
| PATCH | `/api/rentals/:id/complete` | Yes | Mark car returned (sets vehicle back to `available`) | 200, 400, 404 |

#### Book Vehicle Request Body
```json
{
  "vehicle_id": 1,
  "start_date": "2026-05-01",
  "end_date": "2026-05-05",
  "customer_name": "David",
  "customer_email": "david@test.com"
}
```

## Date Collision & Cost Calculation Logic

### 1. Date Range Overlap Check
An existing rental conflicts with a requested reservation if:
- `rental.status` is either `booked` or `active`
- `start_date <= existing_end AND end_date >= existing_start`

If any conflicting record exists, the API rejects the request with:
`400 Bad Request: Vehicle already reserved during this timeframe`

### 2. Day Span & Dynamic Cost Calculation
- Day count is calculated as:
  `diffDays = Math.round((new Date(end_date) - new Date(start_date)) / (1000 * 60 * 60 * 24))`
  `rentalDays = diffDays === 0 ? 1 : diffDays`
- Total cost:
  `total_cost = rentalDays * vehicle.daily_rate`

### 3. State Transitions
- On booking creation: vehicle status transitions to `rented`.
- On completion (`PATCH /api/rentals/:id/complete`): rental status transitions to `completed`, and vehicle status transitions to `available`.
- On cancellation (`PATCH /api/rentals/:id/cancel`): rental status transitions to `cancelled`, and vehicle status returns to `available` if no remaining active bookings exist.

## Validation Testing Guide

1. Populate `.env` with Supabase project credentials.
2. Run database migration in Supabase SQL editor using `schema.sql`.
3. Register and login via `/api/auth/register` and `/api/auth/login`.
4. Create 3 vehicles using `POST /api/vehicles`.
5. Book Vehicle #1 for `2026-05-01` to `2026-05-05`.
6. Attempt booking Vehicle #1 for `2026-05-03` to `2026-05-07`. The server returns `400 Bad Request` with message `Vehicle already reserved during this timeframe`.
7. Import `postman_collection.json` into Postman to run automated tests.
